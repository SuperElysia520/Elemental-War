# UGS PvP bridge wire contract v1

No client Rainyun HTTP. Cloud Code FpsPvp accesses only Cloud Save Private Custom `fps_pvp_bridge_v1`. Rainyun .NET outbound worker owns PartyStore/PartyMatchmaker and one-time UGS tickets. NGO dedicated server uses loopback /api/ugs/* only. UGS identity comes only from Cloud Code context.playerId, not args. UGS long tokens never leave UGS client APIs and are never UDP payload.

## Cloud Save items
`bridge`: {version:1,epoch:<32hex random at bridge process boot>,expiresAt:<unix milliseconds>}. Worker refreshes lease every <=5s, duration15s. Same existingAccountStore process lock prevents second local instance; deployment only one worker per environment. If existing live lease from another epoch: fail startup rather than overwrite. Startup may wait old15s expiry explicitly. Lease expires => submit fails bridge_unavailable. Worker clears own lease on shutdown best effort. First bridge creation only this one authorized worker.
`p_<playerId>`: {version:1,epoch,playerId,requestId:<client32hexUUID>,username:<3-20ASCII username cosmetic for unsaved default>,operation,args:<JSONobject>,createdAt:<unixms>,expiresAt:<created+30000>,state:"pending"|"done",response:null|{status:<HTTPint>,body:<JSONstring>}}. CloudCode derives playerId and key. Client never submits profile, team, server slot, playerId or epoch. Stored profile read server-side from Protected fps_profile_v1; if missing valid default only. Expected profile match null. .NET never persists UGS accounts in accounts.json.

Cloud Code parameters: action String Required (submit/status); requestId String Required; operation String optional; username String optional; args JSON optional. Status only requires action/requestId. Allowed commands current/rooms/create/join/ready/queue/cancel/leave/fail/ticket/game-ticket. Args only join:{partyId:32hex},ready:{ready:boolean}; allother args empty object. ticket is matched admission; game-ticket is normal custom-room or in-lobby profile refresh. No endpoint permits raw client identity/profile.

Cloud Code reads bridge first, requireversion1/valid32hexepoch/futurelease. submit validates, then reads own slot. Same request ID returns current state idempotently. Different live pending same epoch => request_busy. Completed/expired/old epoch may replace via actual writeLock. Missing slot first create cannot be atomic inCloudSave: allowed recoverable same-player superseded, never return mismatched result; re-read after write and reject superseded. Payload bound <=4KB and slot reply <=64KB. Each player one outstanding operation. Backend scans private items (pagination), validates slot key matches playerId, correctepoch, pending, liveTTL and command. Strict no legacyJWT fallback. Worker processes sequentially per scan then CAS writes done using fetched writeLock. CAS conflict never unconditionally overwrites. Duplicate request IDs within epoch cache execution/result in worker for60s so response CAS retry does not redo mutations or mint new tickets. Worker deletes expired/completedold slots with fetchedwriteLock; no full mailboxclear. Onrestart epoch old commands never execute. Done replyexpires30s past submit fine. Worker rejects response >64KB and limit rooms list tofirst50 ifneeded.

Cloud Code reply: {ok:true,code:"",state:"pending"|"done",requestId,body:<done response.body string else "">,status:<done response.status else202>}. Fail: {ok:false,code:<fixed>,state:"",requestId,body:"",status:<appropriate>} codes auth_required/invalid_request/request_busy/request_expired/request_superseded/bridge_unavailable/bridge_restarted/service_unavailable. Only same owner/request/epoch result; no raw errors. Expected .NET business errors remain ok:true/done status4xx with body JSON ApiError {code,message}. Script never returns other player'sslot or server lease internals.
