# RifleGirl PVP 客户端与服务器部署

目标服务器：Windows Server 2022，公网 IP `{{PUBLIC_IP}}`。本文件描述需要通过远程桌面执行的交付步骤，不表示雨云已经上线。新的账号服务必须先完成可信 HTTPS 部署，客户端才能注册、登录和云端保存角色。

## 这次必须一起替换的内容

- `Client/`：本次新客户端的**完整目录**，从 `Start-FPS.cmd` 启动。
- `Server/`：本次新专服的**完整目录**，从 `Start-PvpServer.cmd` 启动。
- 独立账号服务包 `AccountService-WindowsServer2022.zip`：由项目 `Server/AccountService/publish/` 提供，里面有详细 `AccountService.md` 和 `Deployment/` 脚本。

不要只复制 EXE。客户端/专服旁的 `_Data`、`UnityPlayer.dll`、`MonoBleedingEdge` 等必须一起保留。账号服务包不包含 Unity 游戏服，游戏服也不包含账号后端。不要继续使用旧 `Builds/RainyunTrial` 中的客户端或专服 ZIP：即使版本号同为 `0.1.0`，它们也不支持这次的账号协议。新客户端会拦截发现协议不匹配的服务器。

开发验收构建中的自动测试只有显式命令行参数才会启动；正常入口仍使用真实账号登录。正式分发时不要带 `DoNotShip` 目录、本机测试数据库、运行日志或自动测试账号密码。

## 服务器操作者：先账号，后游戏服

1. 通过 RDP 文件复制/磁盘重定向上传账号 ZIP 与新 `Server/`。建议分别放在 `C:\FpsAccount\App` 与 `C:\FpsPvp\Server`，不要混放程序、证书和档案。
2. 按账号包中的 `AccountService.md` 安装 .NET 10 ASP.NET Core Runtime 与证书工具，先测试签发，再由操作者阅读条款、确认正式 IP 证书申请，最后注册账号服务/自动续期任务。账号数据目录在程序目录外，更新时必须保留。
3. 按需要在雨云防火墙与 Windows Defender 防火墙放行 **TCP 80/443**（证书验证/账号 HTTPS）及 **UDP {{GAME_PORT}}/{{DISCOVERY_PORT}}**（游戏/房间查询）。这些交付启动器不会修改防火墙。**5080 只绑定 127.0.0.1，不开放公网。** TCP 3389 保留现有远程维护设置，PVE 广播 47777 无需为本次云 PVP 开放。
4. 从服务器以外的电脑检查 `https://{{PUBLIC_IP}}/health` 返回 `{"status":"ok"}` 且证书可信。不要关闭证书校验，也不要用 HTTP 公网地址替代。
5. 在新 `Server/` 内双击 `Start-PvpServer.cmd`。它确认同机 5080 可连接后，进程内设置 `FPS_ACCOUNT_SERVER_URL=http://127.0.0.1:5080`，以 `-batchmode -nographics -port {{GAME_PORT}}` 启动新专服。注册/密码接口仍只通过公网 HTTPS。
6. 查看 `server_{{GAME_PORT}}.log`，确认 `0.0.0.0:{{GAME_PORT}}` 和 `0.0.0.0:{{DISCOVERY_PORT}}` 已监听，并且没有启动失败；看到进程启动提示不等于端口已经成功监听。若同端口旧专服仍运行，先用其原有方式停止，再启动新目录。

`Stop-PvpServer.cmd` 只停止本目录启动器记录的进程，并验证其 EXE 路径，不按名称结束所有同名进程。停止游戏服会中断当前对局；账号服务、已保存服装和配装不会被删除。专服启动器适合当前试运行，**没有配置游戏服开机自启或故障自动恢复**，服务器重启后需重新启动并验收；账号服务及证书续期则使用账号包配置的计划任务。

如果计划任务、脚本签名或下载文件策略阻止脚本执行，请按 Windows 的报错检查并遵守服务器策略。启动入口仅对自身进程使用 `RemoteSigned`，不修改机器执行策略或组策略。

## 玩家：使用带账号地址的入口

从完整 `Client/` 目录双击 **`Start-FPS.cmd`**。启动器先验证 `https://{{PUBLIC_IP}}/health`，然后仅在游戏进程中设置 `FPS_ACCOUNT_CLIENT_URL=https://{{PUBLIC_IP}}`。它不永久修改电脑环境变量，不保存用户名、密码或登录令牌。

项目中的默认账号地址仍留空，防止把开发回环服务误作为正式服务。**直接双击 `FPS.exe` 不会获得启动器配置，将提示账号服务尚未配置。** 如需桌面快捷方式，请指向 `Start-FPS.cmd`。以后也可在确认 HTTPS 真正上线后，把正式 HTTPS 地址写入设置资源并重新构建，届时才可以省掉入口脚本。

第一次进入游戏，在大厅的角色页面注册/登录，搭配 RifleGirl 外观与主武器/瞄具后点击保存；只有成功收到云端保存确认的档案才用于加入房间。PVP 配装为步枪或狙击枪加手枪。另一台电脑登录同一账号应取回保存的外观与配装。

如果启动器提示账号服务未就绪，需由服务器操作者完成证书/服务/公网连通检查；启动器不会跳过 HTTPS 校验或自动改成本地开发地址。游戏内按 Esc 解锁鼠标，点击右上的退出对局按钮返回大厅；对局掉线也会结束本地会话并返回大厅，账号登录状态继续保留。

## 公网验收顺序

1. 两台电脑用新入口登录两个不同账号；修改外观与配装、保存、关闭后重新登录核对恢复。
2. 创建 PVP 房间并加入，选择相反队伍，确认双方看到对应 RifleGirl 外观和大厅配置。
3. 开始对局，确认步枪/狙击枪、手枪与各自瞄具、射击/换弹/切枪、击杀/重生及远端同步。
4. 一方退出返回大厅，另一方仍正常；全部退出后专服恢复空闲，再创建下一局。另检查意外停止专服时客户端会回到大厅，重启专服后可重新加入。
5. 再检查证书续期任务和账号服务重启后的档案保留。只有这些公网操作实际通过后，才向玩家宣布云端与联机可用。

账号证书有效期较短，必须持续检查账号包中的续期状态。更新程序时同时替换匹配客户端/游戏服，账号数据保持在独立目录中。此交付文件不自动登录 RDP、不上传文件、不替用户接受 CA 条款，也不执行任何服务器设置。

## 构建通过后的打包入口

开发者应先完成同一份源码的客户端与专服构建及联机验收，再在项目根目录执行：

```powershell
& ./Server/AccountService/Deployment/Prepare-GameDelivery.ps1
& ./Server/AccountService/Deployment/Package-GameDelivery.ps1 -ReleaseId 'RifleGirl-PVP-20260926'
```

默认输出到 `Builds/RifleGirlMigration/Packages/`：客户端 ZIP、专服 ZIP、账号服务 ZIP、`SHA256SUMS.txt`、`package-manifest.json` 和本说明。客户端与专服 ZIP 内各有说明及启动入口；解压后的根目录就是各自运行目录。交付批次由 `ReleaseId` 写入两份说明，应将同批客户端与专服一起分发；仅相同的应用版本字符串不能证明构建兼容。

脚本排除调试符号、DoNotShip、日志/PID 和已知测试/私密数据路径，不修改源构建。账号 ZIP 的交付副本会去除其中的 PDB，原账号包保持不变，因此使用本次 `SHA256SUMS.txt` 核对上传文件。重复运行仅替换指定输出目录中的生成文件，不清空输入或输出目录。
