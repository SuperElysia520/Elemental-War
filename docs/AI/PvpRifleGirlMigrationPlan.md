# PVP RifleGirl、角色自定义与 Demo 枪械迁移规格

更新日期：2026-09-26。状态：方案评估与需求收敛；尚未实施游戏功能。

## 用户已确认

- 本轮先改 PVP。
- 每位玩家使用同一个 RifleGirl 全身角色实例与骨架承担本地第一人称和远端角色表现；自定义服装应体现在实际持枪的身体上。
- 玩家在游戏大厅的「角色」功能中编辑外观，加入房间、进入对局时使用自己的外观。
- 外观绑定玩家账号，换电脑登录也能恢复。
- 目前没有可接入的账号服务，需要新增注册、登录与云端存档。
- 账号采用用户名和密码；账号与云端存档服务部署到此前的雨云服务器。
- 首版直接开放资源包已有服装、脸型和配色，不做服装购买或解锁。
- 使用 Test-FPS Demo 中除霰弹枪外的全部枪械，枪械外观一起更换，支持瞄具。
- 枪械和瞄具在大厅配置，开局携带。
- 主武器在步枪和狙击枪之间二选一，副武器为手枪。
- 对标范围包含射击反馈、开镜、后坐力，以及移动、冲刺、跳跃、换弹、切枪、弹速与散布等实际玩法。

## 核心选择已明确；实施前需核实的工程条件

1. 雨云服务器当前实际系统、资源余量、访问方式、对外 HTTPS 地址和数据库持久化位置；这些不能从历史文档当作现状确定。
2. RifleGirl 动画 Avatar 修复后的导入结果、已有全身动作可复用情况，以及三把枪分别需要补充的动作。
3. 本地第一人称的服装/头发遮挡、布料和不同瞄具的实际视觉表现。

工程建议：在雨云上将账号/档案服务与对局服务器分开管理，持久存档不依赖某个房间进程的生命周期。以经过认证的稳定账号标识关联外观档案，不以可变昵称或临时连接编号代替账号身份，不把本机缓存描述为跨设备云存档。

本轮完成方案评估与规格整理，没有部署服务或更改服务器。后续实施过程中若出现会改变用户可见功能的新选择，再据实际证据询问。

## 本地证据与实施影响

### 大厅和外观同步

- `Assets/Scripts/UI/MainMenuUI.cs:34`、`:35`：角色和服装按钮目前均打开提示菜单。
- `Assets/Scripts/Lobby/LobbyState.cs:25`：大厅成员仅有 ClientId、PlayerName、Team、CharacterIndex，PVP 仍按三种固定角色选择。
- `Assets/Scripts/Lobby/LobbyManager.cs:134`：连接数据还没有账号标识和外观配置。
- `Assets/Scripts/Lobby/LobbyManager.cs:1168`：PVP 开局按 CharacterIndex 选择旧角色预制体。
- 本次在第一方代码及包清单中未发现账号登录或云端存档接入；已有玩家昵称输入不等同于账号系统。

建议将外观保存成带版本的配置：服装套装、服装配色、脸型、发色及可用配件的稳定编号。大厅预览与对局角色共用配置应用逻辑。云端存档属于持久数据，房间成员和网络角色携带本局外观快照；新建对局和重生均保持外观，观察者也能读取当前状态。

服务器校验配置中的资源编号与组合，游戏客户端根据本地资源还原外观；网络上传递配置而非网格和贴图。用户名密码注册登录由账号服务处理，游戏侧使用认证会话访问个人档案。具体后端实现与接口应根据雨云的实际运行环境确定。

### 同一全身角色

- `Assets/Scripts/Player/PlayerController.cs:554`：现状为隐藏本地全身角色并生成独立 Viewmodel。
- `Assets/Scripts/Player/PlayerModel.cs:30`：现有持枪约束使用 Animation Rigging。
- `Assets/Scripts/Player/PlayerNetworkSync.cs:42`：现有角色动画同步依赖旧控制器的参数和状态。
- `Assets/Scripts/Player/PvpPlayerCombat.cs:543`：头部命中区依赖 Humanoid 的 Head 骨骼。

需要将本地视角绑定到全身角色，针对本地视角处理头部和头发遮挡，统一武器挂点、双手握持、上下瞄准、枪口和后坐。镜头控制与身体动画的执行顺序需要明确，避免整个人体被当作旧 Viewmodel 一起旋转或位移。重新标定眼高、胶囊和头部命中区，并验证远端所见姿态。

### RifleGirl 可用外观

来源：`E:/Unity资产/Test-FPS/Assets/CombatGirlsCharacterPack/`。

- 三种现成服装组合：外套组合、裙装组合、运动装组合；各有配套身体网格。
- 五个脸部网格预设；其视觉差异是脸型还是表情仍需在预览中确认。
- 一个发型网格、四个发色材质。
- 衣装材质五套；运动服材质一套。
- 帽子与部分配件可开关。

建议首版按经过验证的完整服装组合切换，脸型、发色和相容配色独立选择，配件遵守遮挡关系。任意上下装混搭尚未确认不会穿模，不能把它当成已有能力。

原示例运动装会关闭配件组；若开放运动装与配件混用，需要补充动作与穿模验证。原演示按钮在从运动装切回时存在同时启用两套身体组的静态逻辑风险，新系统应直接按服装 ID 应用互斥状态，而非沿用按钮点击次数和临时布尔值。

资产准备时需核查动画 Avatar：部分动画引用的来源 GUID 在 Test-FPS 中未找到。目标 FPS 已有匹配 GUID 的 Magica Cloth 2 脚本，但仍需验证数据和布料表现。Toon 材质、shader 与贴图依赖需完整迁移。

### 枪械与动作

Demo 中实际非霰弹枪清单：`Assault Rifle_1`、`Pistol_1`、`Sniper_1`。手雷、近战尚不属于已确认的枪械范围。

现成持枪预制体的瞄具兼容关系：

| 枪械 | 现有瞄具 |
| --- | --- |
| Assault Rifle_1 | 铁瞄、Red Dot 1/2/3、全息、8 倍镜 |
| Pistol_1 | 铁瞄、Red Dot 3 |
| Sniper_1 | 铁瞄、Red Dot 1/2/3、全息、8 倍镜 |

大厅配装界面应按兼容关系提供选择；对局开始时同步武器和瞄具配置。未将枪托、枪口、握把、激光等其他附件自动纳入范围。

Demo 的专用手臂动画采用 Generic 骨架，RifleGirl 为 Humanoid 全身角色；不能直接给全身角色换上 Demo 动画控制器。枪械本体的机械动画与人物握持、换弹动作需要分别适配。RifleGirl 的步枪换弹采用其自带武器的挂点与动画事件，不能原样覆盖手枪和狙击枪的换弹。

Demo 的移动、冲刺和跳跃反馈包含镜头和手持物程序动画，并不提供可直接套用的完整人物腿部动作。全身角色的起跳、落地、冲刺和切枪动作素材仍需核查现有可复用资产并验证。

参考手感由视角后坐、相机 Kick/Spring 与震动、枪械 Kick/Spring、鼠标 sway、呼吸/步行动画、瞄具与 FOV 过渡构成。迁移应依据代码实际读取的参数、程序动画和瞄具组件；部分旧 preset 字段没有使用者，不应复制后当成已还原。

FPS 现有 PVP 命中是服务器复核的即时射线、无额外随机散布；参考 Demo 的代表步枪使用飞行弹丸。既然用户包含实际玩法，对标需要覆盖权威射击判定、射速、弹药、散布、弹速、换弹与武器切换状态，不止本地画面效果。

继续使用 FPS 的 NGO 大厅与专用服务器架构。Test-FPS Pro 的 Mirror 联机实现不能直接替换现有网络系统。

## 建议实施顺序

1. 依据已确认规格核实雨云运行环境和角色动作资源，确定后端与资源适配实现。
2. 修复必要资源引用，建立 RifleGirl 公共骨架、服装资源目录和外观应用逻辑。
3. 新增用户名密码注册登录与云端外观存取，打通大厅角色编辑、房间外观同步、PVP 出生和重生外观保持；新增大厅主副武器与瞄具配置入口。
4. 以步枪先完成同一全身模型的第一人称镜头、握持、瞄准、开火与换弹；该步骤是适配顺序，不缩减已确认的三把枪范围。
5. 扩展手枪、狙击枪与各自可用瞄具，对齐移动、冲刺、跳跃和各武器状态规则。
6. 将飞行弹丸、散布、弹药和换弹接入权威服务器判定，联调本地反馈与远端展示。
7. 用至少两个客户端验证外观、动作、命中和重生；验证 Windows 客户端与 Dedicated Server 构建。

## 验收目标

- 同一账号换设备登录后恢复外观；云端加载/保存失败时明确显示状态，不假报保存成功。
- 两位玩家各自使用不同的服装、脸型和配色，彼此看到正确外观，开局与重生不丢配置。
- 本地持枪手臂来自当前全身角色骨架；衣袖、手套等外观与角色配置一致。
- 非本人客户端能看到完整角色；本地镜头不被脸、头发或衣物持续遮挡。
- 三把目标枪及兼容瞄具能使用；开镜、射击、换弹、冲刺和切枪之间的中断与恢复一致。
- 主武器只能选步枪或狙击枪之一，副武器为手枪；进入对局后实际携带的武器与瞄具符合大厅配置。
- 对照选定的 Demo 枪械和配件验证枪口效果、声音、后坐、开镜摆动、弹速和散布；不能仅凭配置值宣称手感一致。
- 服务器与客户端对射速、弹药、换弹和命中采用一致规则；本地视觉效果不重复结算伤害。
