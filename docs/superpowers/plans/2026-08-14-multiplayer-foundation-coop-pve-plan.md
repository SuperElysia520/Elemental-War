# 联机基础 + 联机 PvE 实施计划

- **日期**: 2026-08-14
- **依据规格**: `docs/superpowers/specs/2026-08-14-multiplayer-foundation-coop-pve-design.md`
- **原则**: 每阶段结束都有可运行、可验证的成果；先解决最大风险（网络改造），再堆玩法；全程不破坏单机路径。

## 阶段 0：网络包接入与双开验证

**目标**：装好 NGO 并证明"两台机器能连上"。

1. 安装 `com.unity.netcode.gameobjects` 1.x（选与 Unity 2022.3 兼容的版本），同时引入 Unity Transport 依赖。
2. 安装 ParrelSync（免费插件），实现本机多开模拟多客户端。
3. 建一个最小验证场景：两个 Editor 实例，一个 StartHost、一个 StartClient，双方各生成一个移动的方块，观察同步。
4. 在 GameSatrt 场景挂上唯一 `NetworkManager`（保持单例，不随场景销毁）。

**验收**：ParrelSync 双开，客机能看到房主方块实时移动。

## 阶段 1：大厅（GameSatrt 场景）

**目标**：能建房、能发现、能加入、能开始。

1. MainMenu 增加三个模式按钮：单机 PvE / 联机 PvE / 联机 PvP（本期置灰"敬请期待"）。单机 PvE 按钮本期点击提示"开发中"或直接进入现有 Game 场景（不破坏现状）。
2. 联机 PvE 面板：创建房间 / 刷新房间列表 / 加入房间。
3. `LobbyManager`（NetworkBehaviour）：建房、成员列表（NetworkList）、准备状态、房主"开始游戏"按钮（2-3 人可用）。
4. `LanDiscovery`：UDP 广播房间信息（房名、人数、是否开局），客户端收到后组装列表；定期清理失效房间。
5. 连接审批：上限 3 人，满员拒绝并提示"房间已满"。

**验收**：三开（或两台设备）能看到同一房间列表，加入后成员列表三端一致，房主点开始后全员进入阶段 2 的切换流程。

## 阶段 2：场景切换与玩家生成

**目标**：进 Game 场景后每个玩家有自己的角色。

1. 用 Netcode `NetworkSceneManager` 把房主发起的"开始游戏"接到场景切换；全员从 GameSatrt 切到 Game。
2. 把 Game 场景里固定摆放的三个角色实例拆成预制体（`PlayerNetworkRoot`），场景内删除固定实例；重新接线 `GameManager.playerModels` 引用（注意场景序列化丢失）。
3. 房主在玩家连接时 `Spawn` 对应角色预制体，按加入顺序分配 1/2/3 号角色，记录 `OwnerClientId`。
4. `PlayerNetworkSync`：`NetworkTransform` 同步位置（开启插值）、动画状态枚举用 NetworkVariable 同步。
5. 输入路径分离：联机模式下本地玩家的输入改由网络组件驱动；单例 `PlayerController` 的输入路径在联机时禁用（`enabled=false`），单机路径完全不动。
6. 本地玩家相机挂到自己的角色上（现有 Cinemachine 相机跟随逻辑复用）。

**验收**：三开进入 Game，各玩家控制各自角色、互相看到移动和动画一致；单机模式回归验证 1/2/3 切换 + AI 跟随与改造前完全一致。

## 阶段 3：战斗与波次系统

**目标**：能打僵尸、僵尸会刷、波次会推进。

1. `HealthLogic`：纯逻辑血量组件（血量/倒地/死亡），联机时房主扣血，单机时本地扣。
2. 改造 `PlayerWeapon`：抽出开火接口。真人开火 = 本地视觉立即播放 + 开火 RPC（含枪口方向/时间戳）上发房主；房主射线判定命中 → 扣血 → 可靠通道广播。枪口火花/弹道/后坐力本地即时。
3. `ZombieNetworkSync` 网络壳：僵尸预制体化，房主 `Spawn`；NetworkTransform + 血量 NetworkVariable + 动画状态枚举同步；死亡 `Despawn`。现有 `ZombieEnemy` 状态机原样保留、只在房主端运行。
4. `WaveManager`（仅房主端）：刷新点数组、第 N 波数量 = 基础数 × N、清波后休整 10 秒、开局倒计时 3-5 秒；数值全部配置字段。

**验收**：三开打僵尸：客机开火本地即时、扣血延迟可接受；僵尸位置/动画三端一致；波次推进节奏正确。

## 阶段 4：倒地、救援与结算

**目标**：完整一局的失败闭环。

1. 血量归零进入倒地状态（不可移动、可被救），动画同步。
2. `RescueLogic`：队友靠近倒地者按交互键 → 读条数秒（可配置）→ 半血复活；救援者移动即中断；房主判定、广播进度。
3. 所有真人玩家同时倒地 → 失败 → 战绩结算界面（存活波次、击杀数）→ 解散房间 → 全员回 GameSatrt 大厅。
4. 波次进行中不允许加入（提示"对局进行中"）。

**验收**：完整走查"进房 → 开战 → 倒地 → 救援 → 团灭 → 结算 → 回大厅"全流程，三端表现一致。

## 阶段 5：断线与容错

1. 客机断线：回大厅提示"与主机断开连接"；房间列表剔除失效房间。
2. 房主退出：全员收到断开通知回大厅（无主机迁移）。
3. 加入时的异常：房间已满、房间已开局、连接超时——分别给提示。

**验收**：拔网线/杀进程测试三种断线场景，UI 提示正确、无残留状态。

## 阶段 6：联机走查与回归（对照规格测试清单）

1. 按规格文档"测试与验证"的 8 条走查清单逐条过。
2. 单机 PvE 回归：切换、AI 跟随、武器、僵尸行为与改造前一致。
3. 波次数值平衡初调（基础数、倍率、血量成长），留配置项供后续调整。

**验收**：8 条走查全部通过，单机回归无退化。

## 风险对照（规格文档第 4 条风险的应对）

1. 输入路径冲突 → 阶段 2 第 5 步显式禁用单例路径并回归验证。
2. 纯视觉子弹 → 阶段 3 第 2 步射线起点/方向与枪口视觉对齐。
3. 场景拆预制体引用丢失 → 阶段 2 第 2 步显式检查序列化字段。
4. 包兼容 → 阶段 0 先跑通 Hello World 再动业务代码。
