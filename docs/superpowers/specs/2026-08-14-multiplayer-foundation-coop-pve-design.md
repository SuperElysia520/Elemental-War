# 联机基础 + 联机 PvE（合作生存）设计规格

- **日期**: 2026-08-14
- **状态**: 待用户审阅
- **子项目编号**: 1 / 3（总规划的第 1 个子项目）

## 背景

项目是 Unity 2022.3 LTS 的 FPS 游戏，目前只有单机基础操作：三个角色模型靠按 1/2/3 切换、非操控角色用 NavMeshAgent 跟随（AI 雏形）、僵尸状态机、纯视觉子弹武器。用户规划了三个模式，本子项目做其中前两个模式的网络地基：

- **联机 PvE**（本子项目交付）：2-3 人合作打僵尸波次，无 AI 队友，一人一角。
- **单机 PvE**（下一子项目交付）：1 人 + 最多 2 个 AI 队友，保留 1/2/3 切换机制。本子项目只负责不破坏它。
- **联机 PvP TDM**（后续子项目）：2 队 × 1-5 人，自由选队，50 分 / 10 分钟上限。本子项目只负责留下扩展点。

## 目标

给项目装上网络底座并交付联机 PvE 的完整玩法闭环：模式入口 → 局域网大厅（建房/发现/加入）→ 进入 Game 场景 → 波次生存 → 倒地救援 → 全员倒地结算 → 回大厅。

## 非目标（明确不做，留到后续）

- 单机 PvE 的实现与 AI 自动战斗（子项目 2）
- 联机 PvP TDM 全部内容（子项目 3）
- 大厅选角 UI、敌方高亮描边（后续功能）
- 公网联机（Relay/端口转发）、主机迁移、断线重连
- 表现层预测与延迟补偿（子项目 3 一起做）
- 战绩持久化、成就、玩家资料

## 关键决策（已与用户确认）

| 决策 | 选择 |
|---|---|
| 网络框架 | Unity Netcode for GameObjects (NGO 1.x，兼容 Unity 2022.3 LTS) |
| 拓扑 | 客户端-服务器；房主（Host）兼任服务器，客机只连房主，客机之间不直连 |
| 传输协议 | UDP（Unity Transport），可靠通道传指令/关键状态，不可靠通道传位置/动画 |
| 同步方式 | 状态同步；房主权威（僵尸 AI、波次、伤害判定、救援判定全部房主端计算） |
| 大厅 | 现有 GameSatrt 场景；局域网 UDP 广播自动发现房间，点击加入 |
| 模式入口 | 现有 MainMenu 三个模式按钮（联机 PvP 本期置灰"敬请期待"） |
| 角色定位 | 三个角色模型为纯外观皮肤，属性完全一致 |
| 联机角色分配 | 按玩家加入顺序自动分配 1/2/3 号角色（选角 UI 留到后续） |
| 波次规则 | 无限波次生存，第 N 波数量 = 基础数 × N；清波后休整 10 秒 |
| 死亡/救援 | 血量归零倒地，队友靠近按交互键救援（读条数秒，可被中断）；所有真人玩家同时倒地则失败 |
| 结算去向 | 战绩界面后解散房间，全员回 GameSatrt 大厅 |
| 断线处理 | 客机断线回大厅；房主退出则全员回大厅（无主机迁移） |
| 人数上限 | 联机 PvE 最大 3 人（连接审批强制）；2 人即可开局 |

## 架构：逻辑与同步分离

核心原则：**玩法逻辑是普通 MonoBehaviour，网络同步只是薄外壳。**

- **逻辑层**（普通 MonoBehaviour）：血量、伤害、僵尸状态机、波次系统、救援判定。不含网络代码，不依赖网络会话。单机模式直接本地跑这套逻辑。
- **同步层**（NetworkBehaviour 外壳）：把逻辑层产出的状态广播给客机。只在联机模式激活。
- 数据流向：客机输入 → RPC 到房主 → 房主逻辑层判定 → 状态变化 → NetworkVariable / RPC 广播 → 客机渲染。
- 子项目 2 的单机 PvE（切换 + AI）因此不受网络改造影响；子项目 3 的 PvP 在已验证的网络底座上加团队/计分/延迟补偿即可。

### 场景与 NetworkManager

- **GameSatrt 场景**：主菜单 + 大厅，放置唯一的 `NetworkManager`（连接期间持续存在）。加入 Netcode 的 `NetworkSceneManager` 统一管理场景切换，不额外挂 `SceneManager` 脚本。
- **Game 场景**：玩法场景。玩家角色、僵尸以预制体形式由房主 `NetworkObject.Spawn()` 生成；场景内不再固定摆放角色实例（现有三个固定角色要拆成预制体）。
- 联机 PvE 用 `StartHost()` / `StartClient()`；最大连接数 3 通过连接审批（Connection Approval）实现。
- `NetworkTransform` 更新率默认 30 Hz，开启插值。

### 单机路径不变式

- `PlayerController` 单例与 `SwitchPlayerModel`（1/2/3 切换）在单机模式下保持现状不动；联机模式不使用该单例路径，本地玩家改由新组件驱动输入。
- 子项目 2 开始前，单机 PvE 的行为必须与今天完全一致（本子项目不得破坏）。

## 组件设计

### 新增组件

| 组件 | 层 | 职责 |
|---|---|---|
| `LobbyManager` | 同步（NetworkBehaviour，仅 GameSatrt） | 建房/刷新房间列表/加入；房间成员列表与准备状态；房主开始游戏；断线回退 UI |
| `LanDiscovery` | 同步（配合 LobbyManager） | UDP 广播"房间存在"（不可靠通道），接收方组装房间列表 |
| `PlayerNetworkRoot`（预制体） | 同步 | 玩家的网络身份：NetworkObject + `PlayerNetworkSync` + `HealthLogic` |
| `PlayerNetworkSync` | 同步（NetworkBehaviour） | NetworkTransform 同步位置；NetworkVariable 同步动画状态枚举、血量、倒地状态；输入 RPC（移动、瞄准、开火、救援）上发房主 |
| `ZombieNetworkSync` | 同步（NetworkBehaviour） | 僵尸网络壳：NetworkTransform + 动画状态枚举 + 血量 NetworkVariable；`Despawn` 处理 |
| `HealthLogic` | 逻辑 | 血量/倒地/死亡状态机，纯逻辑组件；联机时房主扣血，单机时本地扣 |
| `WaveManager` | 逻辑（仅房主端） | 波次生成/计数/休整计时；僵尸死亡监听；`NetworkObject.Spawn` 刷怪 |
| `RescueLogic` | 逻辑（房主判定） | 倒地检测、读条计时、中断条件 |

### 改造组件

| 现有代码 | 改造 |
|---|---|
| `PlayerController`（单例） | 保留单机路径；联机模式改由 `PlayerNetworkSync` 驱动本地玩家输入，不破坏现有单例 |
| `PlayerModel`（动画状态机） | 原样保留；场景中三个固定角色实例拆为预制体；联机时挂同步外壳 |
| `ZombieEnemy` + 状态机 | 原样保留，仅房主端运行；客户端由外壳映射动画状态播放 |
| `PlayerWeapon.Fire` | 抽出可复用开火接口：真人开火 = 本地视觉立即播放 + RPC 上发房主判定；AI 开火 = 逻辑层直接调用（子项目 2 用） |

### 伤害与命中判定

- 房主用射线检测判定命中（从枪口到瞄准点方向），扣血结果经可靠通道广播。
- 枪口火花、弹道拖尾、后坐力、镜头抖动在**本地立即播放**（纯视觉，不等待判定）。
- 击杀/倒地确认会有网络延迟：局域网 5-30ms 可忽略，公网 30-150ms 可接受（PvE 目标为僵尸，无竞速判定，延迟不影响公平）。

### 死亡与救援

- 血量归零 → 倒地（Downed 状态，不可移动、可被救）；所有真人玩家同时倒地 → 失败。
- 救援：队友靠近倒地者按交互键 → 读条数秒（可配置）→ 复活为半血。读条期间救援者自己移动则中断；倒地者全程无法移动。
- 倒地状态、救援进度由房主判定并广播。

## 玩法配置（全部做成可调字段）

- 波次：基础僵尸数（默认 5）、数量倍率（× 波次）、波间休整（10s）、开局倒计时（3-5s）
- 血量：玩家 100 / 僵尸随波次成长；救援读条时长；倒地无复活时限
- 刷新点：Game 场景预设数组

## 错误处理与边界情况

- 客机中途断线：回大厅并提示"与主机断开连接"；房间列表刷新剔除失效房间。
- 房主退出：全员收到断开通知，回大厅（无主机迁移）。波次与房间状态不保留。
- 加入进行中的房间：提示"对局进行中"并拒绝（本期不支持中途加入）。
- 连接审批：已满 3 人拒绝加入，提示"房间已满"。
- 僵尸死亡同步丢包：可靠通道同步死亡事件，保证各端最终一致。

## 测试与验证

- **开发期**：ParrelSync（克隆项目本机多开）模拟 2-3 个客户端；正式验证用两台设备局域网联机。
- **联机走查清单**：
  1. 大厅建房/发现/加入，成员列表与准备状态正确
  2. 进入 Game 场景，各自角色生成，角色外观一致
  3. 客机看到的僵尸位置/动画与房主一致（无漂移、不瞬移）
  4. 开火扣血：房主零延迟、客机延迟可接受，伤害广播一致
  5. 倒地 → 救援读条 → 复活半血，全流程各端一致
  6. 全员倒地 → 结算 → 回大厅
  7. 房主/客机断线场景各走查一遍
- **回归**：单机 PvE 现有行为不被破坏。

## 风险

1. **PlayerController 单例与联机输入路径并存**：两条输入路径可能互相干扰，需在联机模式明确禁用单例路径（`enabled=false` 或输入源分离）。
2. **现有子弹为纯视觉**：命中判定要从零实现，注意射线起点/方向与视觉弹道一致，避免"看着打中其实没中"。
3. **场景固定角色拆预制体**：涉及场景引用（GameManager.playerModels 数组等）重新接线，注意 Scene 序列化丢失。
4. **NGO 与 URP/Animation Rigging 兼容**：包版本需与 Unity 2022.3 匹配，导入后先跑通官方 Hello World 再动业务代码。
